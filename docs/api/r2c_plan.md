## 1. 考え方

- **VLA の重みは変えない。** SmolVLA は flow matching で、雑音から 50 行の行動列を作る。その雑音を選べば、VLA が作れる動きの範囲の中で成功しやすい側を選べる（Wagenmaker ら、DSRL、arXiv:2506.15799）。VLA が覚えていない動きは出ない。
- 差し込む所は `runtime/policy.py` の `SensorPolicy.infer` の 1 か所。いま引いている雑音 (1, 50, 32) を、選んだものに置き換える。
- 学習用の配置はシード 80000〜89999（試しは 79900〜79999、学習に使わない）。評価は自分の成功も足すモデルの評価と同じ評価用の配置 200（シード 171700〜171899）を使う。

## 2. 方式 1: 初期雑音を小さな方策で選ぶ強化学習（試して採らなかった）

| 項目 | 決めたこと |
|---|---|
| 小さな方策の行動 | 雑音そのもの（32 次元、tanh × 1.0）。行動列の 50 行すべてに同じ雑音を使う（原論文の π0 の作りと同じ） |
| 観測 | 方策の状態（手先・向き・指・関節・目標位置の入力 x, y の 17 次元）＋目標位置が見えているか＋推論の番号、19 次元。画像は使わない |
| 学び方 | SAC。重みは CPU で学ぶ |
| 報酬 | 1 手順（1 個を箱へ、30 s）の成功で +1。箱を乱す・違う立方体は 0 で終わり。推論ごとの割引 0.99。真の状態で判定するので、実機には持ち出せない |
| 場面 | 1 手順の試行、LLM なし。2 台の PC で試行を集め、学ぶ役は 1 つ |

結果:
- 1 回目は発散した（critic の損失が約 15.7 億まで増え、直近 100 本の成功 0.82 → 0.13、雑音が ±1 に張り付いた）。原因は、tanh の補正の頭打ち、Q の目標に入れたエントロピー、少ない記録での多すぎる更新。補正の式・Q の目標（エントロピーなし、[0, 1] に切り、試行の結果を半分混ぜる）・損失・更新の回数を直して 2 回目を回した。
- 2 回目は、途中で止める目安の誤りで一度止まり、同じ設定で続けた。学ぶほど成功が下がった: 学ぶ前 11/28（0.39）→ 22/82（0.27）→ 43/305（0.14）。学ぶ前と最後の差は Fisher の p = 0.0018。Q の見積もり（約 0.49）は実際の成功より高いままだった。

## 3. やり方の見直し

原論文の設定と比べ、効いたと見る違い:
- **主因**: 小さな方策と Q が画像を見ていない。同じ雑音でも、出る行動列は場面で変わるので、どの雑音が良いかを学べない。
- Q の目標の半分が自分の選んだ雑音での見積もりなので、外れた高い見積もりが自分を支えた。
- エントロピーの目標が原論文より低く（本作は −32、原論文は −16）、土台の雑音のばらつき（立て直しに効く）を消した。

取り入れの検討: 方策から行動を何本か引き、学んだ価値で選び直す方法（V-GPS、Nakamoto ら 2024）を取り入れる。外れた行動に行けないので安全側。価値は雑音でなく行動列の上で学ぶ（原論文の DSRL-NA と同じ向き）。選んだ行動を方策に覚え込ませる方法（PA-RL）、流れの方策の重みを PPO で学ぶ方法、行動に小さな足し分を足す残差の強化学習は、GPU と時間が足りない・手首の向きの欠けを直せないので入れない。

## 4. 方式 2: 行動列の候補から、学んだ成功の見込みで選ぶ

| 項目 | 決めたこと |
|---|---|
| 候補 | 推論ごとに、ふつうの雑音 N(0, I) から K = 8 本の行動列を 1 回のまとめた推論で作る。候補 0 は土台と同じ乱数 |
| 見込み | その試行が成功したか（0/1）を当てる分類。5 つの網の集まり（試行ごとに Poisson の重みで引き直す）。TD を使わないので、外れた見積もりが自分を支えない |
| 見込みの入力（29 次元） | 手先の位置・向きのずれ・指・目標位置が見えているか・推論の番号・目標位置 − 手先、行動列の 5/10/20 行後までの動き・10/20 行後の目標位置との差・グリッパの指令 5 行 |
| 選び方 | 平均 − 0.5 × ばらつき が最大の候補（自信のない候補を避ける）。40 本溜まるまでは選ばない |
| 対照（学習の間だけ） | シードで決まる 25% の試行は選ばない（土台そのもの）。同じ学習用の配置・同じ時間で比べられる |
| 見る数 | 選んだ試行と対照の、直近 200 本の成功。新しい試行を学びに使う前に当てた AUC |
| 見切り | 選んだ試行が 300 本を超えて直近 200 本が 0.20 未満なら止める。2026-10-25 21:00 に選んだ試行と対照を Fisher の検定で比べ、選んだ方が上でなければ終える |

事前の確かめ（作った模擬の問題）: 入力を状態と行動列の正規化の値（89 次元）にした最初の版は、見込みが「どの試行か」を覚えて行動列の違いを学ばず、0.39 → 0.41 しか上がらなかった。今の 29 次元では、信号のある作りで対照 0.34 → 選ぶ 0.43、信号のない作りで 0.34 → 0.37（下げない）。

限界: 手首の向きは直せない（行動に回転がなく、VLA が出せない動きは選べない）。報酬は真の状態から決めるので実機には持ち出せない。見込みの学習は 1 手順の試行で、評価は 3 個を続ける作業。推論の時間は実測の分布から引くので、候補を 8 本にしても模擬の動きは変わらないが、実際の計算の時間は増える。

## 6. 事後の追記（評価の手順書の 11 節から）

- 土台は初め `R2a`（自分の成功も足したモデル）にしたが、`R2a` は 3 個とも箱へを上げなかったので、`R2a` の上の条件 `Uc` の評価は途中でやめ、判定しなかった。
- 代わりに、土台を `Rdag`（自分の失敗から学び直したモデル）に替えて、方式 2 で見込みを学び直した（1 台目、2026-10-26 14:00 まで）。それまでの学習で使った学習用の配置は使わない。この見込みで選ぶ条件が `Udc`。
- `Udc` の結果: `Ud` 145/200 → `Udc` 152/200（+3.5 pt、95% 信頼区間 −4.3〜+11.3、p 0.45）。差は確かめられなかった（評価の手順書 [`r2_protocol.md`](r2_protocol.md) の比較 D）。
