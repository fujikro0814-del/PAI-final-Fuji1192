# 方策が出した腕の動きを、実機の Panda で再生する（物なし）

この文書は、開発中の測定と事前に決めた確かめの記録を、読みやすくまとめ直したもの。数字と決まりは変えていない。

## 目的と言い方

- 実機に合わせたシミュレーション（設定の名前 `v3_real`）で VLA が出した**関節の指令の列**を、実機の Panda にそのまま流す。実機とシミュレーションの手先の動きが一致することを、スマホの映像と記録の数字で示す。
- 方策を実機で動かすのではない（実機にカメラがない）。資料・動画では「シミュレーションで方策が出した動きを、実機で再生した（物は置かない）」と書く。
- 流し方・記録の形・合否の基準は、生成プログラムの指令の再生と同じ（[replay_format.md](replay_format.md) の第 2〜4 節）。それに加えて、下の「再現した」と言う基準を置く。

## 「再現した」と言う基準（実機で流す前に決めた）

[replay_format.md](replay_format.md) の第 4 節の合否の基準は緩い（手先の差 中央値 2 mm・最大 5 mm、遅延の差 10 ms）。そこで、実機に合わせたサーボを、生成プログラムの指令の再生のうち合わせ込みに使わなかった 32 本で確かめた水準に合わせた基準を足す。

比べる相手は、同じ指令を**物なし**で、評価と同じ腕とグリッパ（`configs/real_v1.yaml` の `arm_servo`・`gripper`。`v3_real` と同じ）に開ループで流したシミュレーションの応答（`scripts/real/resim_replay.py --hand`）。

| 項目 | 「再現した」と言う基準 | 参考: 32 本で確かめた値 |
|---|---|---|
| 手先の位置の差（同じ時刻） | 中央値 ≤ 0.5 mm、最大 ≤ 2 mm | 中央値 0.14〜0.24 mm、最大 ≤ 1.2 mm |
| 手先の、指令に対する遅延の差 | ≤ 2 ms | ≤ 2 ms |
| 関節のずれ（RMS） | ≤ 0.5 mrad | 0.17〜0.28 mrad |
| グリッパの閉じ始め・開き始めの時刻の差 | ≤ 0.1 s | （合否の基準と同じ） |
| 実機のエラー・通信 | エラー 0、成功率の最小 ≥ 0.9 | （合否の基準と同じ） |

- 全部を満たした本だけを「再現した」と書く。満たさない本は、満たさなかった項目と値をそのまま書く（基準を後から緩めない）。
- 判定は通常の速さの本で行う。遅い版（速さ 0.5 倍）は安全の確かめで、判定に使わない。

## 結果（通常の速さで 1 本）

- 遅い版は流さず、通常の速さを 1 本流した。記録（arm.csv・gripper.csv・meta.json・result.json）の SHA256SUMS は一致した。
- 流し方は生成プログラムの指令の再生と同じ（kJointImpedance・limit_rate・cutoff 100 Hz・CPU performance）。見張りは反応せず、反射で止まらずに最後まで流れた（手先の加速度・躍度の指令は、動きの上限の監査で参考にしている上限の 1.05 倍だった）。

| 項目 | 基準 | 結果 | 判定 |
|---|---|---|---|
| 手先の位置の差（同じ時刻） | 中央値 ≤ 0.5 mm、最大 ≤ 2 mm | 中央値 0.18 mm、最大 0.76 mm（掴む・放す瞬間 0.12〜0.27 mm） | 満たす |
| 遅延の差 | ≤ 2 ms | 0.5 ms（実機 6.5 ms、シミュレーション 6.0 ms） | 満たす |
| 関節のずれ（RMS） | ≤ 0.5 mrad | 0.24 mrad（関節ごと 0.16〜0.32。実機の PC での計算と、シミュレーションの PC での計算が一致） | 満たす |
| グリッパの閉じ始め・開き終わりの時刻の差 | ≤ 0.1 s | 0.18・0.07・0.11・0.17 s | **満たさない** |
| エラー・通信 | エラー 0、成功率の最小 ≥ 0.9 | エラー 0、最小 0.92 | 満たす |

- 決まりどおり、この本を「再現した」とは書かない。書き方は「**腕の動きは再現した**（手先の差 中央値 0.18 mm・最大 0.76 mm、遅延の差 0.5 ms、関節のずれ 0.24 mrad）。グリッパの動き出しは実機の方が最大 0.18 s 遅く、基準（0.1 s）を満たさなかった」。
- グリッパの差の理由（実機での観察）: 実機のグリッパが grasp の指令から閉じ始めるまでの遅延は 0.28・0.35 s。生成プログラムの指令の再生（通常の速さ 9 本）でも 0.17〜0.42 s とばらつき、シミュレーションのグリッパ（約 0.17 s）より遅いことがある。
- スマホの動画: 30.1 s・1920×1080・30 fps（音声は使わない）。

## 決まり

- **物は置かない**（立方体・箱なし）。グリッパの grasp は空振りになる（期待どおり）。
- 実機で流す手順と記録の形は、[replay_format.md](replay_format.md) の第 2・3 節と、実機の PC の再生プログラムをそのまま使う。新しく書かない。
- **安全**（[replay_format.md](replay_format.md) の第 2 節）:
  - CPU を performance にする。開始姿勢へは上限の 10% の速さで移る。関節 1 は [−2.80, −1.66] rad の中だけ。
  - 指先は台座の面から約 2 cm まで下りる。扇形の範囲に物・取り付け面がないことを確かめてから流す。
  - **まず遅い版（速さ 0.5 倍）を 1 本**、停止ボタンに指をかけて流す。エラーなしで比べが通ってから通常の速さ。
  - 見張り（関節 1 の範囲・指令と測った関節角の差 0.05 rad・停止ボタン）で止まったら、そこで止めて報告する。通常の速さで流し直さない。
- **個人情報**: 撮影に顔・名札・画面・部屋を特定できる貼り紙を映さない。音声は使わない（動画では消す）。

## 手順 1. 書き出し（シミュレーションの PC）

1. **試行を選ぶ**: 動画の主な場面と同じ配置（シード 171318）で、立て直しの仕組みをすべて入れた条件の試行。実機で流すのは、最初のサブタスク（赤を箱へ）の約 25〜30 s に絞る（開始姿勢から、赤を掴んで箱の上で放し、腕が止まるまで）。全部（88 s）は長く、物がないと落下と組み直しの意味も映らないため。
2. **書き出し**（`scripts/real/export_policy_replay.py`）:
   - 選んだ試行を `v3_real` で回し直し、指令の制限（`runtime/limiter.py`）が出した 1 kHz の関節の指令と、グリッパの指令（時刻・幅・速さ）、シミュレーションの応答（関節角・速さ・手先・指の幅）を記録する。回し直しなので経過は評価の記録と少し違う（動画の映像と同じ扱い）。
   - 切り出し（最初のサブタスクの終わりで止め、腕が止まりきるまで手先を保ってから 0.2 s 止める）、実機への変換（関節 1 を −130°）、確かめ（関節の可動域、関節 1 の範囲、libfranka 0.9.2 の速度・加速度・躍度の上限、指の幅 0〜0.08 m、最後に静止）は、生成プログラムの指令の書き出し（`scripts/real/export_replay.py`）の関数をそのまま使う。外れたら書き出さずに理由を残す（切り詰めて合わせることはしない）。
   - シミュレーションの応答は、実機に合わせた腕とグリッパで付ける（`scripts/real/resim_replay.py` と同じ）。
   - 遅い版（`scripts/real/export_replay_slow.py` の引き延ばし）も作る。
   - `scripts/real/build_replay_zip.py` で zip にする（sha256 つき）。列は [replay_format.md](replay_format.md) の第 1 節と同じ。
3. **シミュレーションの映像**: 同じ指令の列を `v3_real` で流して描画する。視点は、手順 2 で決めたスマホの位置に近づける（左右に並べるため）。

## 手順 2. 実機での再生（実機の PC）

1. **受け取り**: zip を展開し、`sha256sum -c SHA256SUMS` が全部 OK であること。
2. **準備**:
   - CPU を performance。FCI を有効にし、停止ボタンを手元に置く。扇形の範囲に物がないこと。
   - スマホを三脚に固定する。横向き、1080p・30 fps 以上。画角は腕の全体と台座の面が入る斜め前（腕の正面から左に約 45°・やや上から）。位置と高さをメモする（シミュレーションの視点合わせに使う）。
   - 映り込み（人・画面・貼り紙）がないことを、録画前に画面で確かめる。
3. **遅い版を 1 本**: スマホの録画を始めてから流す。記録（`arm.csv`・`gripper.csv`・`meta.json`）を取り、次で比べる。`pass` でなければ止めて、記録と result.json を返す。

   ```
   python3 compare_replay.py --replay <名前>.csv --real <記録>/arm.csv --real-gripper <記録>/gripper.csv --real-meta <記録>/meta.json --out <記録>/result.json
   ```

4. **通常の速さを 1〜3 本**: 3 と同じく録画してから流し、同じく比べる。各本の結果（pass / fail / incomplete）をメモする。
5. **返すもの**: 各本の記録フォルダ（arm.csv・gripper.csv・meta.json・result.json）、スマホの動画（元のファイル、編集しない）、スマホの位置と高さのメモ、気づいたこと（音・揺れ・見張りの反応など）。

## 手順 3. 映像にする（シミュレーションの PC）

- 実機（スマホ）とシミュレーションを左右に並べ、流し始め（腕が動き始めるフレーム）をそろえる。
- 字幕は「シミュレーションで方策が出した動きを、実機で再生（物は置かない）」と、比べの数字（手先の位置の差の中央値・最大、遅延の差）。
