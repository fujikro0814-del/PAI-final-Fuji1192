# 実機で再生する列と、実機の記録の決まり

この文書は、開発中の測定と事前に決めた確かめの記録を、読みやすくまとめ直したもの。数字と決まりは変えていない。

シミュレーションの生成プログラムが出した関節の指令を、実機の Panda にそのまま流し、シミュレーションの腕の追従が実機と同じかを、同じ指令の列で比べる。方策が出した指令の再生（[h1_policy_replay.md](h1_policy_replay.md)）も同じ列と同じ手順を使う。

- 書き出し: `scripts/real/export_replay.py`（生成プログラムの指令）、`scripts/real/export_policy_replay.py`（方策の指令）
- 比べ: `scripts/real/compare_replay.py`
- 実機に合わせた値: `configs/real_v1.yaml`

## 1. 書き出す列

### `<名前>.csv`（1 kHz、1 行が 1 ms）

| 列 | 単位 | 中身 |
|---|---|---|
| `t` | s | 流し始めからの時刻。行 i は (i+1)·1 ms（libfranka の 1 回目の呼び出しの周期を 1 ms とする） |
| `tail` | 0/1 | 1 は生成プログラムが終わった後の行。腕が止まりきるまで手先を保ち、さらに 0.2 s 止める |
| `recorded` | 0/1 | 1 は学習データに入った部分。成功データは全部。立て直しデータは、失敗を起こして記録を始めた後 |
| `q_cmd0`〜`q_cmd6` | rad | **実機に流す関節の位置の指令**（指令の制限の出力。関節 1 は −130° ずらした後） |
| `q_sim0`〜`q_sim6` | rad | シミュレーションで測った関節角（関節 1 はずらした後）。500 Hz を 1 kHz に線形に補間 |
| `dq_sim0`〜`dq_sim6` | rad/s | シミュレーションで測った関節の速さ（同じく補間） |
| `ee_cmd_x/y/z` | m | `q_cmd` の順運動学の手先（libfranka の O_T_EE の決まり、台座の座標） |
| `ee_sim_x/y/z` | m | `q_sim` の順運動学の手先（同じ決まり） |
| `ee_sim_qw/qx/qy/qz` | — | `q_sim` の手先の向き（四元数、w が先） |
| `width_sim` | m | シミュレーションの指の開き幅（2 本の和） |

- 手先の決まり: libfranka の O_T_EE（Franka Hand の既定）と同じ。シミュレーションのハンドの原点（フランジ）から、ハンドの z 軸の向きに 0.1034 m。向きはハンドと同じ。
- 関節 1 以外は、シミュレーションの値そのまま。台座の座標の手先は、シミュレーションの手先を縦の軸まわりに −130° 回したものと同じ。
- 桁: rad・m は小数 10 桁。丸めによる躍度の誤差は 2 rad/s³ 以下で、上限（3750〜10000 rad/s³）に比べて無視できる。

### `<名前>_gripper.csv`（グリッパの指令）

| 列 | 中身 |
|---|---|
| `t` | 指令を出す時刻 [s]（上の `t` と同じ時計） |
| `kind` | `grasp` か `move` |
| `width`・`speed` | 幅 [m]・速さ [m/s] |
| `force`・`eps_inner`・`eps_outer` | grasp のときだけ [N]・[m]・[m] |

### `<名前>_ds.csv`（10 Hz、学習データと同じ列）

合わせる前のシミュレーションの学習データ（LeRobot v3.0、10 fps。`src/recovla/data/convert.py`・`vla_state.py`）と、同じ列名・順・単位の表。**中身は、学習データのその本の行そのもの**で、それを実機の台座の座標へ回してある。

| 列 | 学習データの欄 | 単位・定義 |
|---|---|---|
| `frame_index` | `frame_index` | フレームの番号（0 から） |
| `timestamp` | `timestamp` | frame_index × 0.1 s（エピソードの始めから） |
| `t_stream` | （なし） | そのフレームの時刻。流し始めからの時刻で、1 kHz の `t` と同じ時計。立て直しデータは記録を始めた時刻から |
| `eef_x`・`eef_y`・`eef_z` | `observation.state` 0〜2 | ハンドの原点（フランジ）の位置 [m]、台座の座標 |
| `eef_rot_dev_x/_y/_z` | 3〜5 | 手先の向きの、真下からのずれ（q·conj(Q_DOWN) の回転ベクトル、Q_DOWN = x 軸まわりに π）[rad] |
| `finger_left`・`finger_right_neg` | 6・7 | 開き幅の半分と、その符号を反転したもの [m] |
| `joint1`〜`joint7` | 8〜14 | 関節角 [rad]（joint1 は −130° ずらした後） |
| `dx`・`dy`・`dz` | `action` 0〜2 | そのフレームから次の 0.1 s の、手先の指令（x_des）の変化 [m]（台座の座標） |
| `drx`・`dry`・`drz` | 3〜5 | 0 |
| `gripper` | 6 | 次のフレームの時点の開閉の指令（+1 閉、−1 開） |

- 座標: 台座の座標 = Rz(−130°)・シミュレーションの座標。手先の向きも −130° 回るので、`eef_rot_dev_z` は約 −2.27 rad になる（学習データではほぼ 0）。学習データと同じ座標に戻すときは `real_to_ds.py --frame task` で +130° 回す。
- 出さない欄:
  - 画像（`observation.images.image`・`image2`）: カメラがない。
  - 目標位置の入力（`observation.state` の 15・16 番、`cue_x`・`cue_y`）: 画像から作る。
  - `episode_index`・`index`・`task_index`: 学習データの帳簿の欄。指示文は manifest の `instruction` に書く。
- フレームの時刻: 記録器（`record/episode.py`）は物理の 1 ステップの後、20 Hz（25 ステップごと）に記録を取り、その時点で届いている最新の測定（センサのモデルの値）を読む。学習データのフレーム k は記録の 2k。成功データは試行の始め（t = 0）から、立て直しデータは記録を始めた時刻（物理の 50 ステップの倍数）から 0.1 s ごと。
- 照合: 書き出しでは同じ生成プログラムをシミュレーションで回し直し、次を確かめた（manifest の `dataset_match`）。
  - フレーム数・行動・最初のフレームの状態が、学習データの行と一致する。
  - 2 フレーム目からの状態の差が、センサのモデルの雑音の大きさ（2 mm・2 mrad 以内）に収まる。差が残るのは、雑音の引き方が描画の有無で変わるため（生成は描画あり、書き出しは描画なし）。

### `manifest.json`

各本について次を記録する: シード・種類・色・作り直しの回数、生成の記録と一致したか（所要時間・フレーム数）、**開始姿勢 `start_q_real`**、流す長さ、確かめの結果（関節の速度・加速度・躍度の上限に対する比の最大、上限の 9 割を超えた刻みの割合、使った関節 1 の範囲）、手先の高さの範囲、CSV の SHA-256。ほかに、コードの版と設定の SHA-256 も記録する。外れて書き出さなかった本は、`exported: false` と理由を残す。

## 2. 実機で流す手順（実機を動かすプログラムが守ること）

1. CPU を performance にする。
2. **開始姿勢へゆっくり移る。** 関節で補間し、速さは上限の 10%。移る先は manifest の `start_q_real`。関節 1 は範囲 [−2.80, −1.66] rad の中だけを通る。移った後、0.5 s 以上止める。
3. 流す: `robot.control(関節の位置の口)`。設定は次のとおり。
   - `controller_mode = kJointImpedance`
   - `limit_rate = true`（上限の中の指令は変えない。通信が抜けたときだけ効く）
   - **`cutoff_frequency = franka::kDefaultCutoffFrequency`（100 Hz）**。最初は 1000 Hz（フィルタなし）と決めたが、実機の初回で関節 2 の指令の側（`q_d`）が 8 s から 3〜10 Hz で揺れ始めて大きくなり（最大 23 mrad。`q` は `q_d` に 2.3 mrad 以内で付いていた）、見張りで止めた。100 Hz では 38 本とも揺れなし（`q_d` と返した指令の差 0.8 mrad 以下）。フィルタの遅延（約 1.6 ms）は、実機の遅延 6〜8 ms に含めて比べる。
4. 呼び出しごとに時刻を `t += period.toSec()` で進め、`q_cmd` の行 `round(t / 1 ms) − 1` を返す。通信が抜けて period が 2 ms になったときは、行を 1 つ飛ばす。最後の行を返すときに `MotionFinished`。
5. グリッパ: `<名前>_gripper.csv` の時刻に、別のスレッドで別の `franka::Gripper` の接続から指令を出す（指令は止まるまで返らないため）。立方体なしでは grasp は空振りになる（期待どおり）。
6. 見張り: 毎周期、次を見張る。どれかが起きたら止め、エラーとして記録する。
   - 測った関節 1 が範囲の外に出そうになった
   - 指令と測った関節角の差が 0.05 rad を超えた
   - 停止ボタン
7. **手先の高さ:** 指先は台座の面から約 2 cm の高さまで下りる（manifest の `ee_z_cmd_range_m`）。扇形の範囲の台座の面の高さに、物や台座の取り付け面がないことを確かめてから流す。
8. **加減速の強さ:** 指令の制限は、上限の 0.99 倍いっぱいの関節の加速度・躍度を使う（manifest の `ratio_max`・`frac_over_90pct`）。手先の加速度は最大 約 11 m/s² になる。それまでの実機の試験は手先 1.0 m/s² 以下、関節の加速度は限界の 32% 以下だったので、初回は成功データの 1 本で、停止ボタンに指をかけて流す。

## 3. 実機の記録の決まり（比べの入力）

### `arm.csv`（1 周期 1 行）

| 列 | 中身 |
|---|---|
| `t` | 流し始めからの時刻 [s]（`period` の和。上の `t` と同じ時計） |
| `q0`〜`q6` | `RobotState::q` [rad] |
| `q_d0`〜`q_d6` | `RobotState::q_d` [rad] |
| `O_T_EE0`〜`O_T_EE15` | `RobotState::O_T_EE`（libfranka の並び＝列ごと。位置は 12・13・14 番） |
| `success_rate` | `RobotState::control_command_success_rate` |
| `cmd0`〜`cmd6`（任意） | プログラムが返した指令 [rad] |

### `gripper.csv`（`readOnce` を回すスレッド。読めるたびに 1 行）

| 列 | 中身 |
|---|---|
| `t` | 上と同じ時計 [s] |
| `width` | 幅 [m] |
| `is_grasped` | 0/1 |

### `meta.json`

```json
{"replay": "n_20000_red_r0.csv", "replay_sha256": "<manifest の csv_sha256>",
 "errors": [], "limit_rate": true, "cutoff_frequency": 100, "cpu_governor": "performance"}
```

`errors` には、libfranka の例外の文字列や、見張りで止めた理由を入れる。何も起きなければ空。

## 4. 比べの基準（データを見る前に決めた）

`compare_replay.py` の基準:

| 基準 | 合格の条件 |
|---|---|
| エラー | 0 |
| 成功率 | 最小 ≥ 0.9（流し始めから 0.1 s 以降） |
| 遅延 | 手先の、指令に対する遅延の差（実機とシミュレーション）≤ 10 ms |
| 位置 | 同じ時刻の手先の位置の差: 中央値 ≤ 2 mm、最大 ≤ 5 mm、掴む・放す瞬間 ≤ 3 mm |
| 向き | 向きの差 ≤ 1° |
| グリッパ | 閉じ始め・開き終わりの時刻の差 ≤ 0.1 s |

- グリッパの開き終わり: 開く指令の時点の幅が、実機とシミュレーションで 2 mm より違うときは比べられない。立方体なしの実機は閉じ切っているので、このときは開き始めで代え、どちらを使ったかを結果に書く。
- 参考として、実機と指令、シミュレーションと指令の遅延と、遅延を引いた後のずれも出す。
- どれかが fail なら `fail`。それ以外で、評価できない基準（記録がない）があれば `incomplete`。
- **10 Hz の表（参考、合否なし）:** `<名前>_ds.csv` があれば、実機の記録を `real_to_ds.py` で同じ列にし、列ごとの差（絶対値）の中央値・最大を `dataset_view_10hz` に出す。
  - シミュレーションの側は記録器の値（センサのモデルの雑音・遅延を含む）。実機の側は、フレームの時刻以前の最後の測定。
  - 行動は、実機も同じ指令を流したので再生の値を写す（差 0）。代わりに、測った手先の変化（`meas_dx/dy/dz`）と指令の変化の差を出す。

## 5. 実機の記録を学習データの列にする（`real_to_ds.py`）

```
python3 real_to_ds.py --arm arm.csv --gripper gripper.csv --replay-ds n_20000_red_r0_ds.csv --out real_ds.csv [--frame base|task]
```

- フレームの時刻: 再生の `_ds.csv` の `t_stream` をそのまま使う（シミュレーションの記録器と同じ瞬間）。各時刻 T に、`arm.csv` の t ≤ T の最後の行と、`gripper.csv` の t ≤ T の最後の読みを使う（記録器が、その時点で届いている最新の測定を読むのと同じ取り方）。
- 手先: `O_T_EE` から計算する。位置はフランジ（O_T_EE の位置 − 0.1034 m × O_T_EE の z 軸）、向きは O_T_EE の回転。リポジトリの順運動学は使わない。
- 指: 幅の半分ずつ。関節: `q` をそのまま。行動: 再生の値を写す（実機の側に x_des がないため）。
- 列は `<名前>_ds.csv` と同じで、後ろに `meas_dx/dy/dz`（測った手先の次の 0.1 s の変化）を足す。

## 6. 実機の初回用の遅い版（`scripts/real/export_replay_slow.py`）

通常の版は関節の加速度・躍度が上限の 0.99 倍に届く。実機の通信は約 0.16% 抜けるので、上限の近くで抜けると不連続の反射で止まりうる。そのため初回は遅い版で流す。

- 引き延ばし: 各本の `q_cmd` を、開始姿勢（t = 0 で止まっている）から 3 次のスプライン（両端の速さ 0）でつなぎ、時間 2 倍（速さ 0.5 倍）で読み直す。行数は 2 倍で、行 2i+1 は元の行 i と同じ値。グリッパの指令の時刻も 2 倍（速さ・力は同じ）。
- 19 本の最大は、上限に対して関節の速さ 0.19・加速度 0.31・躍度 0.42 倍。手先の加速度は 約 3.1 m/s²。躍度が 0.125 倍にならないのは、スプラインが元の躍度の段（指令の制限の上限いっぱいの切り替え）でふくらむため。
- シミュレーションの応答: 生成プログラムは回さず（判断し直さない）、同じ配置・開始姿勢から、引き延ばした指令を物理の 1 ステップに 2 つずつ流す。口は生成と同じ位置のサーボ（`WorldRig.apply_joint_commands` → `physics_step`）。立方体はなし（接触を切り、重力を打ち消して浮かせる）で、実機と同じ空振りになる。
- 口の確かめ: 1.0 倍・立方体ありで同じ口に流すと、元の応答を再現する。差は丸めの大きさ（manifest の `reproduction_1x`）。
- 列は通常の版と同じ。`_ds.csv` は作らない（時間 2 倍の動きに対応する学習データのフレームがない）。
- 比べは `compare_replay.py` の同じ基準。結果の JSON に `"variant": "slow_0.5x"`・`"slow_variant": true` と出る。
- 順番: まず成功データの 1 本（`n_20000_red_r0`）を遅い版で流し、エラーなしで比べを確かめる。そのうえで通常の速さの一式を流す。

- 各本の `<名前>.csv`・`<名前>_gripper.csv`・`<名前>_ds.csv`（生成プログラムの再生は 19 本）


## 8. 実機に合わせたシミュレーションの腕（`configs/real_v1.yaml` の `arm_servo`）

実機の記録（生成プログラムの指令の再生 38 本）で、シミュレーションの腕のサーボを合わせた。

- 合わせる道具: `scripts/real/fit_servo.py`。実機と同じ指令をシミュレーションに開ループで流し、関節角を実機の `q` と同じ時刻で比べる。
- 変える場所: `src/recovla/harness/arm_real.py` の `ArmServo`（ゲイン・指令の先送りと遅延・重力補償）。`harness/world.py` は変えないので、合わせる前の世界はそのまま残る。
- 見つけたこと: センサの設定の `gravity_compensation: true` は効いていなかった。MuJoCo はモデルを組み立てる時点の `ngravcomp` が 0 だと補償を計算しないが、シミュレーションの世界は組み立てた後に `body_gravcomp` を立てていた。
- 応答の付け直し: `scripts/real/resim_replay.py --src <書き出した列> --out <付け直した列>`。指令・グリッパの指令は元のままで、シミュレーションの応答の列だけを付け直す（立方体なし）。`--hand` でグリッパも実機に合わせた値にする。
- 比べ: `compare_replay.py` をそのまま使う。付け直した列は sha256 が元と違うので、manifest の `source_csv_sha256`（元の列）と `meta.json` の `replay_sha256` が合えば、同じ指令を流した記録として扱う。
